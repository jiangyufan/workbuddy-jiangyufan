# WorkBuddy + ima 组合神仙用法！我把100多篇教程丢进去，知识库开
最近我突然发现，自己可能一直把知识库用浅了。我在 ima 里为小微智能体维护了一个 「小微智能体指南」知识库。

在过去的一年多的时间里一共累计 180 篇教程：怎么创建智能体、配置知识库、设置语音回复，以及各种新功能和玩法。

最开始做这个知识库，想法其实很简单：把散落在各处的教程集中起来。用户遇到问题，不用再翻公众号历史文章，直接进知识库搜索、提问就行。这已经很好用了。但最近体验 WorkBuddy 时，我突然冒出一个想法：如果不只是让人「看」这个知识库，而是把整个知识库直接交给 WorkBuddy，会发生什么。

于是我真的试了一圈。结果发现知识库好像开始自己干活了。

它不只是回答问题，还可以一次性分析上百篇教程、找出内容缺口、重新设计新人学习路线、整理 FAQ，甚至继续生成文章、PPT 和针对不同人群的使用指南。

## ima + WorkBuddy 到底怎么配合。
连接其实很简单。进入 WorkBuddy 的「更多」找到 ima，完成授权即可。

*专家·技能·连接器｜日常办公 代码开发 设计创意*

以前我理解 ima，更多是一个 AI 知识库。文章、PDF、教程、笔记都可以长期存进去，需要时直接问。但现在，ima 本身已经越来越像一个「知识管家」：不只是搜索，还可以跨文件理解、整理和分析知识。而 WorkBuddy 更进一步。它可以直接把这些知识拿出来，完成具体任务。

现在 WorkBuddy 可以调用 ima 中的文件，甚至整个知识库；任务完成后，新生成的报告、文档和方案，还能继续存回 ima。

于是整个流程变成了：资料进入 ima → WorkBuddy 调用知识完成任务 → 产生新资料 → 再沉淀回 ima。

以前知识库更像一个仓库。现在，它开始变成一个工作台。所以我干脆拿自己的「小微智能体指南」做了一次实验。

## 先让 AI 给知识库做一次体检。
我没有一上来就让它写文章。而是先问了一个更重要的问题：我这 100 多篇教程，到底整理得怎么样。做产品久了很容易出现这种情况。

教程越写越多，自己反而越来越难从全局看清楚：哪些已经讲过。哪些重复了。哪些地方还缺一块。新用户到底应该从哪里开始。

于是我把整个知识库交给 WorkBuddy。新建任务，在输入框左下角「+」中打开 ima 连接器。

使用ima连接器阅读我提供的「小微智能体」知识库。先不要帮我生成新的教程，也不要只是简单总结现有文章。请站在「产品运营 + 新用户」两个视角，对整个知识库做一次系统体检。重点完成以下任务： 1. 梳理当前知识库已经覆盖了哪些内容 2. 检查内容完整度 3. 从新用户视角检查学习体验 4. 找出知识缺口 5. 输出一份完整的「小微智能体知识地图」 6. 最后生成一份《小微智能体知识库体检报告》。

发送之后，它把知识库中的 180 个教程条目全部读取出来，并先整理出整个内容骨架。

随后又生成了一份 HTML 版「知识库体检报告」。

它从「产品运营 + 新用户」两个视角，把 180 条内容重新盘了一遍，包括内容覆盖、完整度、学习体验、知识缺口和后续重构方向。

更有意思的是「知识地图」。它没有继续按照原来的文章目录排列，而是按照：用户到底要解决什么问题。把 180 条教程重新拆成了 10 个主题域，同时标出了每个主题目前还缺什么内容。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/RWodr0jgXg6vRrZ48pKry7EjIbicibpwg00HiaUjszg7r3ZDOGSJicQ280ITIsibhibUaakY4ewriaRdH5iaagS6CF8kEdSIXq8vV7EGZBISuAicFxxQ/640?wx_fmt=png&amp;from=appmsg#imgIndex=5)

这样我一眼就能看出：哪些内容已经写得很完整，哪些地方是下一阶段应该重点补的选题。这件事给我的感受很明显。以前我们用 AI，最常见的是：帮我多写一点。但现在我发现，还有一种可能更有价值：先帮我看清楚，我已经拥有什么，还缺什么。当上百篇资料堆在一起时，人很难重新建立全局视角。

但这件事，恰恰很适合 Agent。

## 上百篇教程，直接变成一套新手课程。
接着我又发现了另一个问题。知识库中的文章，大部分是按照「我什么时候写的」排列的。但第一次接触小微智能体的人，并不关心发布时间。他真正关心的是：我到底应该先学什么。知识库里可能已经有创建智能体、配置知识库、语音回复、主动消息等大量教程。每篇单独看都没问题。

但对一个小白来说，更大的问题是：他甚至不知道自己应该搜索什么。于是我继续让 WorkBuddy 换一个角度。

不按照文章顺序，而是按照真实使用流程，把整个知识库重新组织成：入门 → 创建 → 配置 → 发布 → 运营 → 进阶。

我给它的指令是：

请假设你是一名「AI 产品课程设计师」，你的任务是： 把目前知识库中零散的小微智能体教程，重新组织成一套适合零基础用户学习的完整路径。目标是让一个从来没有使用过小微智能体的人，可以按照这套路线，从 0 开始完成： 了解产品 → 创建第一个智能体 → 完成基础配置 → 发布使用 → 学会运营 → 掌握进阶玩法。请完成以下任务： 1. 阅读并理解现有教程 2. 重新设计学习路径 3. 每个阶段请给出： - 阶段目标 - 用户需要掌握的能力 - 推荐阅读的教程 - 推荐阅读顺序 - 一个实际操作任务 - 常见问题和容易踩的坑 4. 检查学习路径是否存在断层 5. 最终生成一份：《小微智能体从 0 到 1 学习教程》 要求： - 必须以现有知识库内容为依据 - 不要虚构不存在的功能 - 尽量引用对应教程名称 - 面向没有技术基础的普通用户 - 表达简单、清晰、可以直接照着学习。

前一步解决的是：应该读哪几篇。这一步进一步解决：到底应该怎么学、怎么操作。

为了让教程不只是文章清单，我又让它回到 ima 中精读了 8 篇核心文档，把里面真实的操作步骤和图片重新组织进新教程。

你会发现：资料一篇都没有增加，但换一种组织方式，价值完全变了。所以我现在越来越觉得：知识库最重要的，不是资料够不够多，而是这些资料能不能根据任务被重新组织。

## 同一套教程，自动生成不同版本。
这个玩法我觉得特别适合做产品的人。因为同一个产品，面对的用户可能完全不同。以小微智能体为例。有人只是想做一个自己的 AI 好友；有人是自媒体博主，想做数字分身、回答粉丝问题；还有企业用户，希望拿它做客服、企业知识助手或者业务智能体。过去怎么办。

可能要分别写三套教程。但仔细想想，它们底层依赖的其实还是同一套产品知识。所以我又让 WorkBuddy 基于整个知识库，为不同人群重新组织内容。

现在请站在产品运营和用户增长的角度，把同一套产品知识重新组织给不同类型的用户。目前重点考虑三类用户： 1. 普通用户 没有技术背景，希望快速做出一个自己的 AI 好友或个人智能体。2. 自媒体 / 知识博主 希望创建自己的 AI 分身，用于回答粉丝问题、沉淀个人知识、提供内容服务。3. 企业用户 希望将小微智能体应用到客服、企业知识库、客户服务或内部业务场景。第一步： 请先分析这三类用户之间的差异。分别说明： - 他们为什么会使用小微智能体 - 最关心的问题是什么 - 最适合的使用场景是什么 - 哪些功能对他们最重要 - 哪些复杂功能暂时不需要了解 第二步： 基于「小微智能体」知识库已有教程，分别为三类用户设计一套上手指南。每份指南包含： 1. 这个用户为什么值得使用小微智能体 2. 推荐从哪个功能开始 3. 第一步应该做什么 4. 第二步应该做什么 5. 推荐学习哪些教程 6. 最适合尝试的 3 个场景 7. 常见问题 8. 下一步进阶方向 注意： 不要只是把同一份教程换三个标题。三套指南的： - 内容重点 - 教程顺序 - 使用案例 - 表达方式 都应该根据用户需求重新组织。所有功能必须来源于现有知识库。没有资料支持的内容请不要自行补充。最终用HTML输出： 《普通用户版小微智能体上手指南》 《自媒体博主版小微智能体上手指南》 《企业用户版小微智能体上手指南》。

这件事让我觉得很有意思。以前知识库是：一套内容，给所有人。现在开始变成：同一套知识，可以针对不同的人自动“变形”。知识不再只是被查询一次。而是在被不断重新组合、加工和复用。

这次研究 ima + WorkBuddy，我最大的感受是让我重新理解了一件事：我们为什么要做知识库。以前知识库的逻辑很简单。文章存进去。PDF 存进去。教程存进去。资料越来越多。然后……很容易就变成另一个收藏夹。但 Agent 出现以后，这件事开始变了。

ima 负责把知识长期沉淀下来。

WorkBuddy 则负责在真正需要工作的时候，把这些知识重新调出来、重新理解、重新组合，再产生新的结果。

我一开始给小微智能体做「小微智能体指南」知识库，只是希望用户能更方便地找到教程。

继续这么用下去，它完全可能慢慢变成：新手学习系统、FAQ、内容素材库、产品运营知识库，甚至一套持续更新的内容生产系统。
