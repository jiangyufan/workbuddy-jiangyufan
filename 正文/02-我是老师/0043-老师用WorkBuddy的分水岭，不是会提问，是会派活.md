# 老师用WorkBuddy的分水岭，不是会提问，是会派活
## 从"问我答"到"接手一件事"
很多老师用 AI，还停在"问我话、我回答"的阶段："帮我写一个网店运营的实训案例""帮我出一套直播带货的教学任务书"——AI 确实能答，但价值有限。

真实的项目化案例开发不是一个个孤立的文案任务，而是一条链：企业调研 → 岗位能力分析 → 课程标准对标 → 项目任务拆解 → 情境设计 → 任务书撰写 → 评价量规制定 → 教学资源配套 → 学生手册编写 → 实施反馈迭代。分段问 AI，每段都要重新描述一遍上下文，一切工具上下文就断了。

所以要讲的不是"怎么问 AI"，而是"怎么给 Agent 派活"。

## 先搞清楚：AI回答一句话，Agent接手一件事
Chatbot 的基本工作单位是一轮问答，适合快速解释概念、改写文字。Agent 的基本工作单位是一件任务：它会围绕目标持续推进——读文件、查资料、调用工具、生成文档、发现问题、调整计划，再继续执行。

它之所以能做事，是因为有三样东西：工具（读 Word、转 Markdown、联网搜索、生成 PPT、写 HTML、处理 CSV）；状态（知道自己做到哪一步、还缺什么材料）；循环（在"计划—执行—检查—修正"里反复逼近目标）。

## 最该先练的：SGP派活结构
给 Agent 派活不需要很复杂的提示词技巧，说清楚三件事就够：

S——情境：这些材料是什么、要做什么项目。"这份是课程标准，这份是企业调研报告。"

G——目标：最终要产出什么、给谁用。"产出一份能直接上课的网店运营项目化教学任务书。"

P——过程怎么走："你先帮我把三份材料看一遍，告诉我整体框架是什么样的，第一步最应该干什么。"

合起来，就是你用自己的口吻给一个新同事交代任务。这段话一点不复杂，但比"帮我写个网店运营项目案例"稳定得多。

## 最关键的一块：人知道、AI不知道
提示词决定 AI 下一步往哪走，上下文决定 AI 在这个任务上能走多远。把知识按"人知道/不知道"和"AI 知道/不知道"分成四个象限：

人知道 AI 也知道的（通用项目化教学理论、常见案例结构）——无需给上下文；人不知道 AI 知道的（行业报告、电商平台规则）——让 Agent 搜集补充；人知道 AI 不知道的（本校课程标准、合作企业信息、实训平台条件、学生基础、区域产业特点）——必须放进工作空间；人和 AI 都不知道的——老师和 AI 共同探索。

最关键的是第三块：人知道、AI 不知道。这些信息不给它，它只能用通用经验补空白。WorkBuddy 在工作空间让你放材料，不是一句空话——把课程标准、企业调研报告、往届案例、评价量规模板、学生名单都放进去。这才是老师真正的价值：把老师抬回到"做专业判断"的角色上。
