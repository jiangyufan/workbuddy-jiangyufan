# 给高考志愿做了个抽签机：一句话生成能转发的网页
填志愿那几天，最纠结的往往不是分数够不够，而是在一堆差不多的学校之间反复摇摆。有个做高考报名工具的朋友，干脆给自己做了一个'志愿抽签机'：屏幕上像转盘一样随机蹦出一所211高校，点一下'开始抽签'就换一所，抽过的还记进历史。更省事的是，这个能直接在手机打开、能转发的网页，全程没写一行代码，也没开网页托管账号。

它的做法值得拆开看，因为这是一条完整的链路：从导入一个技能文件，到拿到发布参数，再到一句提示词生成页面、一句话把它发布上线。每一步都能照搬到其他'想快速做一个能访问的网页'的场景。

下面按真实顺序还原整个过程。所有界面、参数名和提示词都来自原作者的操作记录，没有补充他没做的步骤。

## 一、先装一个能把网页发布出去的技能
整个链路的第一块拼图，是让 WorkBuddy 具备'把本地 HTML 发布成在线链接'的能力。这一步靠的是一个叫 WebOS 的技能。

做法是下载这个技能的压缩包文件，然后在 WorkBuddy 的技能面板里导入。导入时有个硬性要求：压缩包里必须包含一个 SKILL.md 文件，而且这个 Markdown 文件要有 YAML 格式的技能名称和描述，否则不会被识别成合法技能。

这一步和平时在技能市场点安装不一样——它是本地导入一个现成的技能包。作者用的压缩包含有发布网页所需的完整逻辑，导进去之后，WorkBuddy 就多了一项'把 HTML 发布成可访问链接'的能力。

## 二、拿到发布要用的两个参数：osid 和 token
技能装好还不能直接用，发布需要两个身份参数：osid（网站库 ID）和 token（令牌）。这两个参数是发布目标的坐标和钥匙，缺一个都发不出去。

获取方式在 WebOS 的开发者文档里，作者说照文档操作一两分钟就能拿到。拿到后在网站库的'文档'页面能看到对应信息，直接复制 osid 和令牌即可。有一处必须留意：令牌相当于接口的密码，拿到它就能操作网站库里的数据，所以不要在公开场合泄露，也不要随手交给不可信的助手。

这一步本身不是 WorkBuddy 的操作，而是去发布平台领一对凭证。高锰酸钾式的紧张没必要，但令牌确实要当密码保管。

## 三、一句提示词让 AI 把网页做出来
有了生成能力，下一步是把想要的东西说清楚。作者给 WorkBuddy 的提示词原文是这样的：'我需要生成一个高考报名抽签功能网页，默认是全部的211高校，用户也可以手工配置高校，配置高校全部在本地存储。'

这句话里其实压了三个明确需求：一是默认要有一份完整的211高校名单，二是允许使用者自己增删高校，三是这些自定义配置存在本地。正是第三句，决定了页面不需要后端数据库——配置存在浏览器本地，刷新也还在。

AI 接到需求后直接产出了一个 HTML 文件，并在预览里给出了成品效果：蓝色卡片式的抽签盘，中间显示校名，下面一个醒目的'开始抽签'按钮和'再抽一次'，旁边是统计区（候选高校112所、已抽次数）和抽签历史，历史里按顺序记着每次抽中的学校和时刻。手机上打开也是同样的效果。

## 四、再一句提示词把它发布上线
页面做好后还只是本地文件。发布同样是一句话：'使用 webos 技能发布这个页面。'

WorkBuddy 先读取本地的 HTML 文件，然后去找之前保存的 osid。它在历史记录里找到了网站库的 osid，但还缺 token，于是停下来问作者要。这里作者把 osid 和 token 一起发给它，发布随即完成。

完成后返回一个可以直接访问的在线链接，页面就正式上线了——可以把链接发给别人，对方用手机就能打开抽签。整个过程从导入技能到拿到在线链接，没有手动开过任何网页托管后台。

## 五、一个容易被忽略的省事点：参数只给一次
发布成功后，作者多问了一句：下次发布还要不要重新给 osid 和 token？WorkBuddy 的回答是：不用了，参数已经写进了用户级的记忆文件（.workbuddy 目录下的 MEMORY.md），跨项目、跨会话持久保存，下次发布页面时会自动读取。

这点很关键。它意味着 osid 和 token 这类'每次都要重复填的凭证'，只需要交代一次，后面发布别的页面都能复用。对于要连续做多个在线页面的场景，省掉的是每一轮都要重新翻令牌、粘贴参数的麻烦。

不过这也再次说明令牌的分量：它被明文记进了本地记忆文件，保管好这台设备，就等于保管好了这把钥匙。

## 六、这条链路能搬到哪里
抽签机只是个引子。真正可迁移的，是这条'技能导入 → 凭证准备 → 提示词生成 → 提示词发布'的四步链路。

任何'想快速得到一个能访问、能转发的网页'的需求，都能套进去：活动报名页、投票页、随机分组工具、班级抽签、门店展示页。区别只在于第三步提示词里描述的功能不同，第一、二、四步几乎不用改。

另外有一个判断值得留下：如果这个页面只需要自己看，做完 HTML 就够了，不必走发布那一步；一旦需要发给别人、需要在手机上打开，发布这一步才产生价值。先想清楚'给谁看'，再决定要不要上线，能省不少往返。
