# 从 OpenClaw 到桌面办公第一，它解决的是「从回答到交付」那一段
## 导言：它更关注完成一项工作，而不是回答一个问题
写一份行业研究，它不会停留在生成一段文字，而是继续搜索资料、整理信息、输出报告，再生成 PPT；处理一批本地文件，它可以完成读取、分类、重命名、汇总；重复出现的工作，还可以整理成 Skill 或 Workflow，下次直接调用。

简单来说，WorkBuddy 更关注的是完成一项工作，而不是回答一个问题。这种定位，也让它更适合那些每天都在和文档、表格、PPT、公众号、知识库打交道的岗位。运营、市场、行政、财务、教师，甚至没有开发经验的普通用户，都可以从一个具体任务开始，把重复工作逐步交给 AI。

## 一条任务是怎么被跑起来的
从能力架构上看，一条任务要跑通得经过六层。第一层是 Ask、Plan、Craft 三种模式，决定它动嘴还是动手。第二层是选模型，可以走 Auto 也可以指定具体模型。

第三层是思考与执行层，内置专家、专家团和各种技能，多角色协作拆任务。第四层是数据与外部服务层，把工具和服务接起来，包括本地文件、上传文件、网页搜索、QQ 邮箱、腾讯会议、飞书、微信公众号等。第五层是交付结果，直接产出 Word、Excel、PPT、PDF、图片、网页、数据表。

贯穿这套架构的核心逻辑有三条：场景驱动，围绕真实工作流；生态协同，连接器打通微信、文件、工具、业务数据；重点是天天能用，完成任务比聊得多漂亮重要。

## 从公开数据看，它已经进入真实使用阶段
易观分析发布的《中国办公智能体平台市场研究报告 2026》显示，WorkBuddy PC 端月访问量达到 885 万，在桌面办公智能体产品中排名第一；腾讯随后公布的数据也显示，平台用户留存率持续保持在较高水平，人均 Token 使用量快速增长。

这意味着，越来越多用户已经开始把 WorkBuddy 用在真实工作里，而不仅仅是体验新产品。环比增速 831%，领先第二名 2.6 倍，第三方调研口径下桌面端办公智能体排名第一——这些数字背后是使用深度的变化，不只是下载量。

## 它并不是突然出现的
如果把时间往前拨几个月，会发现 WorkBuddy 的出现其实有一条很清晰的发展路径。很多人第一次关注腾讯的 AI Agent，是因为今年爆火的 OpenClaw。当时腾讯大厦门口出现了不少开发者排队安装 OpenClaw 的场景，「今天去腾讯装龙虾了吗」一度成为社区里的热门话题。

OpenClaw 展示了 AI Agent 操作电脑、调用工具、自动执行任务的能力，也让很多人第一次意识到，AI 已经不仅仅是聊天工具。但它更偏向开发者产品。环境部署、模型配置、权限管理，对于普通用户来说依然存在一定门槛。

之后腾讯陆续推出了 QClaw、CodeBuddy，再到今天的 WorkBuddy，这条产品线也越来越清晰。如果说 OpenClaw 证明了 Agent 能做什么，那么 WorkBuddy 更关注另一个问题：怎样让更多人真正用起来。从开发者到普通用户，从技术验证到日常办公，从一个 Demo 到一款能够长期使用的产品。

## GPT、Claude 已经很好用了，为什么还要用它？
这是很多人的第一个疑问。ChatGPT、Claude 在写作、推理、编程等方面已经非常成熟，对于开发者来说，它们依然是每天都会打开的工具。但模型能够给出高质量答案，并不意味着一项工作已经完成。

很多办公任务还涉及查找资料、读取本地文件、整理表格、生成文档，以及在多个工具之间反复操作。WorkBuddy 主要解决的是这一段「从回答到交付」的过程。

对于很多非技术用户来说，他们不会部署 Agent，不熟悉 API、MCP 或各种开发框架，每天面对的是公众号、Word、Excel、PPT、腾讯文档、企业微信，以及大量重复出现的办公流程。WorkBuddy 把模型调用、工具连接和 Workflow 编排封装进一个产品，用户可以直接描述目标，再由 Agent 拆解任务、调用工具并交付文件。

## 和 Codex 到底差在哪
有社区用户把这种区别概括为两种不同的「工作世界」：Codex 更早进入代码仓库和终端，围绕软件工程建立执行与验证流程；WorkBuddy 则从普通用户每天接触的文件、文档和通信入口出发。前者更适合开发环境，后者更接近中文用户的日常办公桌面。

**逐项对比的话：**核心定位上，WorkBuddy 是 AI 办公团队，Codex 是技术型 AI 执行平台。最擅长的事，前者是调研、文案、报告、PPT、运营，后者是编程、文件处理、自动化、搭建工具。使用门槛前者相对较低，后者稍高但不一定要懂编程。

工作方式上，前者是选择专家、技能、办公场景，后者是打开项目文件夹让 Agent 直接工作。国内生态上，前者对飞书、微信、钉钉等更友好，后者更偏 ChatGPT、GitHub、IDE 和开发工具。多 Agent 场景，前者是多个行业专家协作，后者是多个 Agent 处理不同项目或代码分支。

文件修改偏好上，前者偏向生成办公成果，后者更擅长直接读取和修改本地项目文件。自动化能力上，前者侧重办公流程，后者侧重脚本、代码、定时任务和工具搭建。适合人群分别是运营、策划、市场、管理者，和程序员、创业者、效率工具重度用户。

与此同时，WorkBuddy 也在持续接入腾讯文档、企业微信、微信公众号等腾讯生态能力。对于国内企业来说，模型能力只是选择工具的一部分，权限管理、数据安全、已有软件生态和团队使用门槛，同样会影响一款 AI 产品能否进入实际业务。用户完全可以根据任务选择产品，也可以将它们组合使用。

## 真实场景演示：三类任务怎么跑
会议内容处理。用 tencent-meeting-mcp 查询会议号对应的已结束会议，先返回主题、时间和主持人，确认是目标会议后，再查询录制列表。有权限就获取转写全文、分段信息和智能纪要；无权限则停止读取并返回所需授权，不尝试绕过。一次会议后的信息整理就变成了标准流程。

资讯整理。可以建一个「GitHub AI 趋势每日播报」定时任务：每天早上 7 点调用 github-ai-trends 技能，拉取当日热门的 AI / ML / LLM 仓库前 20 个，以排行榜形式直接发到对话里，每个项目包含排名、项目名（附链接）、Star 数、Fork 数、主要语言和一段简介。脚本用 GitHub 公开 API，纯标准库、无额外依赖、也不需要登录令牌。

内容生产。用 wechat-search、xiaohongshu-search 采集近 30 天的选题数据，公众号 44 篇加小红书 33 篇加 4 篇高评论笔记的洞察，输出一份本周选题池可视化报告，含原链接、内容结构和互动信号，直接落到 outputs 目录并打开预览。

文档生成。给一句需求「帮我生成一份公司团建活动策划的 Word 文档框架，约 80 人，包含活动目标、主题建议、流程安排、分组游戏、预算清单、人员分工、风险预案和注意事项」，它会直接交付一份 9 章加 6 表格的框架稿，所有需要领导拍板的事项用红色标记，并在最后一章汇总成一张拍板清单。

## 有人已经这么用了
在企业的分享现场，能看到很具体的落地方式。有人分享了一套公众号自动化工作流，从选题、资料收集、内容撰写，到 AI 审稿、配图、排版、发布，每一个环节都交给不同的 Skill 和 Agent 协同完成，人工只负责最终审核，大幅减少了内容运营中的重复劳动。

有人做了一个政务公文 Skill。输入活动主题、人数、时间等基础信息后，能自动生成经费请示、预算明细、活动筹备台账等标准材料，把过去需要反复修改的工作变成一套可以重复执行的流程。

还有人把它用到电商视觉生产，通过多个 Skill 串联商品图片处理、营销素材生成等流程，让 AI 参与整个视觉内容制作，而不仅仅是生成一张图片。

越来越多开发者开始分享自己的 Skill、Workflow 和项目实践，也意味着 WorkBuddy 正在从一款工具，逐渐形成属于自己的开发者生态。

## 写在最后
如果你还没有使用过 WorkBuddy，不妨从一个案例开始，找到一个自己每天都会遇到的问题，亲手跑一遍，看看 Agent 能如何帮助你完成这项工作。

对于普通用户来说，它降低了第一次使用 Agent 的门槛。你不需要先理解复杂的技术概念，只需要从自己的工作场景出发，找到一个相似案例，再根据自己的需求进行调整。
