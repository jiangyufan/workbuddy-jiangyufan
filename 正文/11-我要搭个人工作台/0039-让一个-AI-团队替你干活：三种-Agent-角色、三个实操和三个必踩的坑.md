# 让一个 AI 团队替你干活：三种 Agent 角色、三个实操和三个必踩的坑
## 一个人搬家具 vs 一个团队搬：多 Agent 到底改变了什么
前面讲的都是「你和 AI 一对一」的模式：你下一句指令，AI 执行一个任务。但碰到大活，你只能在边上等着，看 AI 一件一件做，像看一个人搬家具，心累。

多 Agent 模式就是把「一个人搬」变成「一个团队搬」：你当老板，AI 团队给你干活。你＝CEO，AI 团队＝执行层——你来拍板「干什么」，WorkBuddy 自动拆任务、分给不同的 AI Agent，它们并行执行，做完汇总交到你手上。

**区别很直观：**你说「搬沙发」，AI 去搬，搬完你说搬桌子，AI 再搬——这是串行，慢；你说「把客厅搬空」，AI 自动分出三个 Agent：一个搬沙发、一个搬桌子、一个搬椅子，同时搬——这是并行，快。

*串行与并行的区别：一个人一件件搬，和拆分给三个 Agent 同时搬*

## 三种 Agent 角色：Plan 想方案，Explore 找信息，General-Purpose 动手干
WorkBuddy 内置三种 Agent 角色，不同活派给不同人。General-Purpose 是全能选手，能读写文件、写代码、执行命令，是干活主力，大部分任务都派给它。

Explore 负责快速扫描文件系统、搜代码，适合「找东西」——查文件、搜代码、定位问题。Plan 负责分析任务、拆解方案，适合复杂任务的规划阶段：先梳理再执行。

**一句话记住：**Plan 想方案，Explore 找信息，General-Purpose 动手干。

## 实操一：一句话创建一个开发团队
不需要手动配置，直接说：「帮我创建一个开发团队，做一个小红书风格图片生成工具——前端：一个网页，可以输入文字、选配色、预览效果；后端：Python 脚本，用 Pillow 库把文字拼到模板图上；测试：部署到本地，打开浏览器验证功能。」

WorkBuddy 会自动完成四件事：创建团队（3 个 Agent 加 1 个 Leader 协调）；拆任务——前端 Agent 写 HTML，后端 Agent 写 Python，测试 Agent 验收；三个 Agent 同时开工各干各的；Leader 汇总结果告诉你「做好了」。

## 实操二：用 Agent 团队做竞品分析报告
这是最实用的场景——把大任务拆给多个 Agent 同时推进。指令这样写：「帮我做一个‘国内主流 AI 写作工具’的竞品分析报告：Agent A 市场调研，搜索各 AI 写作工具的最新动态、融资、用户数据；Agent B 产品对比，对比几个主流产品的核心功能、定价、差异化；Agent C 用户评价，搜集真实用户反馈，列出好评和差评 Top 3。三个 Agent 汇总成一份报告，包含对比表和结论建议，保存成带样式的 HTML 文件。」

**时间对比很直观：**原来你自己做——搜资料 30 分钟加整理 20 分钟加写报告 40 分钟，一个半小时；Agent 团队做——三个同时搜、同时整理，5 到 10 分钟。

## 什么时候用多 Agent，什么时候别用
不是所有任务都适合用多 Agent。适合的情况：任务之间没有依赖关系，各干各的效率最大化；单一任务工作量超过 10 分钟，拆成小块能省很多时间；需要同时处理多个数据源，每个 Agent 负责一个方向。

**不适合的情况：**任务只有一步，多 Agent 反而增加协调成本；任务之间有强依赖，B 必须等 A 干完才能开始，串行没意义；临时小任务，「给我查个东西」一句话就够了。

**一句黄金口诀：**能不能同时开工？能——用多 Agent；不能——普通对话。

## 团队管理：看进度、救卡壳、先规划再执行
Agent 干活的时候，你可以在任务列表里看进度，每个 Agent 的状态有进行中、已完成等。如果某个 Agent 卡住了，直接说：「Agent A 怎么停了？看看它现在什么状态，需不需要我补充信息。」WorkBuddy 会检查卡壳原因，给出明确的解决方案。

碰到超级复杂的任务，建议加一个 Plan 环节：先用 Plan Agent 分析需求、拆成可执行的子任务，先出方案不用执行；你确认没问题，再让 General-Purpose Agent 团队开工。这个「先想后做」的模式，用在你不确定怎么拆的大任务上。

## 三个真实踩坑：串行、接口不兼容、文件冲突
坑一，团队建好了却只有一个 Agent 干活，其他闲着——原因是任务被拆成了有依赖的串行步骤。解决：确认任务确实独立，把「A 写完代码→B 测试→C 部署」改成「A 写前端页面、B 写后端接口、C 写单元测试」三个同时进行，互不依赖。

坑二，Agent 之间代码不兼容，前端调不通后端接口——原因是没在指令里约定接口规范。解决：分配任务前先定好接口，比如「A 写后端 API，接口格式 GET /api/data 返回 JSON；B 写前端，调用这个地址」。

坑三，多个 Agent 同时改同一个文件，冲突了——原因是两个 Agent 往同一个文件写内容。解决：任务分配时明确各自负责的文件范围——A 只写前端页面文件、B 只写后端接口文件、C 只写测试文件，各写各的不要互相碰。一句话总结：约定先行，分配任务前先定好接口和文件范围。
