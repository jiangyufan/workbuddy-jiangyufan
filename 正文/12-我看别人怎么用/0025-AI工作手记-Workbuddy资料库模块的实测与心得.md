# AI工作手记| Workbuddy资料库模块的实测与心得

## 二、资料库模块更新带来了什么。
这次更新不是加新功能，是把腾讯文档/IMA知识库/腾讯乐享三类工具收拢到一个面板里，让它们跟对话、文件操作连起来。其中腾讯乐享暂时不在我的使用场景里，留待后续再研究，今天重点说 IMA 和腾讯文档两条路径。

第一：从各自分散变成了统一入口。

以前IMA和腾讯文档都是独立入口。虽然先后有开放API或与workbuddy的连接入口,但始终在场景关联上隔着一层。现在入口直观的挂在左侧操作面板里——授权完就能直接访问，不用打开新标签页、不用切工具。

第二：IMA 的读和写双向通了。

以前IMA skill可以「读」——在对话里搜索已有的笔记。但「写」是断的——WorkBuddy 生成的方案想存进 IMA，得手动下载、打开网页端、新建笔记、粘贴。现在一句「存进资料库」就能推过去，反过来授权后 WorkBuddy 也能直接读 IMA 里的内容参与对话。

第三：通路顺畅后，分工逻辑也更明确了。

IMA：不只是原本的公众号等信源文档的即时存储，在workbuddy工作中产出的成果文档、会被反复引用的品牌框架/话术库等经验类文档也可以随时从工作区（workbuddy）存储进ima笔记备忘。便于后续随时语义搜索调取。腾讯文档：需要多人协作编辑、外部审阅的过程稿/成果文档，可以直接指令化将workbuddy中的即时成果传至腾讯文档，减少了中间环节。

以前知识管理靠人的记忆来维持——记得文件在哪、记得 skill 叫什么、记得每次手动上传。现在开始靠系统的结构来维持——入口在面板上、产出能自动入库、对话可以引用，成果文档/知识文档各归其位。

总结来说，在我的工作场景中，会产生以下的变化——。维度。之前。之后。跨工具调用。

Claude + Obsidian + IMA + 腾讯文档各说各话，切换平台+复制粘贴/生成再上传是常态。

侧边栏统一入口，三类知识源可在对话里直接引用，产出物也可回存。IMA 的可见性。一个必须「想起来」才能用的隐形 skill。侧边栏入口，「很难看不见」。产出→沉淀。生成 → 手动下载 → 手动上传。写入路径断在手动环节。对话里直接入库 IMA，回存路径打通。

文件检索。靠记忆定位文件夹，手动打开搜索。按检索场景拆分成独立笔记，语义搜索直接定位。

## 三、摸索之后，如何用这个模块优化已有的工作文档。
除了摸索打通后的路径，我顺手把现有workbuddy的工作区内容按资料库路径优化了一遍。

workbuddy的工作区面板一直存在归档不清晰的问题。虽然可以重命名等方式解决部分，但即时性的任务太多，也会不可避免的存在用着用着，工作区就乱了的情况。

就拿最近差不多同时进行的五六个项目来说，同时期不同任务在跑的就可能有十几份文件，涉及到不同的交付类型或者子任务，为了过程管理方便和平台运行的稳定性可能还会继续拆分成不同的并行任务组——这会导致之后再想找之前的某个过程的某个文件成果，得先想「哪个项目/哪个子任务」→ 定位到对应 task 文件夹 → 打开搜索。

新模块下，今天的归档拆分跑得简单了很多。以一个调试多次的品牌 Messaging 文档为例——。

核心变化是：不再靠「我记得它在哪」来检索，而是靠「我需要什么」来匹配。

## 四、虽然方便了很多，但不足也依旧很明显。
跑了几遍后，感受到便捷之余也免不了踩到了几个坑——不是吐槽，是客观记录当前版本的真实体验：

① IMA：不能从workbuddy直接建文件夹。API 只支持创建单篇笔记，不支持创建笔记本/文件夹。9 篇笔记全堆在「全部笔记」里，需要手动打开 IMA 客户端拖进对应文件夹。项目堆积多了，整理的负担会倍增——简化了路径，但在 IMA 客户端按项目建好笔记本+即时手动整理的工作还是不能少。② IMA：非文本格式入库会「失真」。PPT 和 docx 入库时只能做文本提取，原文件的结构、排版、图片全部丢失。存进去的是「内容」，不是「原件」。③ 文档与 API 不一致。IMA 的 import_doc 接口实际返回的字段叫 note_id，但 skill 文档里写的是 doc_id。第一次写脚本 KeyError 报错，查了返回体才发现对不上。细节，但影响信任感。④ 面板的交互功能目前还是「轻量级」。侧边栏资料库目前本质上依旧只是个连接和切换入口——授权、选知识源、浏览。缺少直接批量操作（批量入库、批量归类）或直接编辑功能。能用，但「好用」还差一点。

## 五、写到最后。
整体体验完后，有一个感受不得不提——。

资料库模块不是一个孤立的功能更新。看得出，它是腾讯在努力打通内部零散办公场景工具生态的一个缩影。WorkBuddy 确实是一个合适的入口——对话界面天然适合调度多个知识源，功能模块的集成广度在同类工具里也算完整。

但完整不等于顺畅。

就目前的体验来说，「平台在努力整合」和「用户真正用得顺」之间，还有一段距离。这段距离一半需要平台持续打磨细节深度，另一半需要用户主动定向调适——搞清楚哪条路径真正跑通了，哪条还只是入口层面的展示，然后围绕真正跑通的部分建立自己的工作流。

我自己目前的跑的IMA 批量入库流程，本质上就是这样一次调适：基于我自己对项目后续应用+资料最大化复用的理解，绕开不足、用通优势、把真实可用的那部分固定下来。

——其实这也是所有知识库构建和管理的逻辑，不是为单纯的【存档】，而是为了之后更高效的复用。
