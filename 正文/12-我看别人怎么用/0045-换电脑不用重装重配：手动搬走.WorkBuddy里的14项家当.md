# 换电脑不用重装重配：手动搬走.WorkBuddy里的14项家当
## 账号只管聊天记录，不管本地家当
换了一台新笔记本，系统装好、软件装好，以为万事大吉。打开 WorkBuddy 一看，对话记录都在——但装的 Skill、MCP 连接器、身份文件、记忆文件，全都不见了。

那一刻才意识到：账号只管「聊天记录」，不管「本地家当」。真正值钱的东西都存在 ~/.workbuddy/ 里，它们不跟账号走，跟硬盘走。换电脑要手动搬。

## 要搬的是14项，不是2项也不是5项
这些目录和文件决定了 WorkBuddy 怎么认识你、能做什么、谁能做。不是两三项，是 14 项，每一项都是在这台电脑上花时间磨出来的。

身份与记忆层（5项）：SOUL.md 核心灵魂设定、IDENTITY.md 身份文件、USER.md 用户档案、MEMORY.md 长期记忆、memory/ 每日日志目录。这 5 项决定 WorkBuddy 认识你的深度——换完电脑如果它们是空的，对话要从零开始，它不认识你了。

## 配置与技能层（5项）
skills/ 目录是自定义技能包，WorkBuddy 能做什么全看这里面有什么；configs/agents/ 是自定义 Agent 设定，比如 code-reviewer、documentation-writer；configs/commands/ 是自定义命令别名；configs/hooks/ 是钩子脚本，比如危险命令拦截、自动格式化；configs/mcp.json 是 MCP 服务器连接配置，定义能连哪些外部工具。

## 运行时与扩展层（4项）
plugins/ 是社区插件包，含下载的第三方扩展；plugins/cache/ 是自动生成的运行时缓存，这一项可以忽略，换电脑后会自动重建；theme.json 是界面主题配置，颜色字体布局；还有自动化任务配置，定时任务、触发条件、执行动作——相当于你的「肌肉记忆」。

## 方案一（推荐）：云盘同步 + 软链接
适合日常多设备切换、换电脑频率高的人。原理是把整个 .workbuddy 目录放进云盘（iCloud/OneDrive/百度云），新电脑从同一云盘拉取后重建链接。以后换电脑就是装云盘 + 重建软链接，零手动搬运。

旧电脑：安装并登录云盘客户端，把 ~/.workbuddy/ 整个目录拖进同步文件夹，等待 14 项全部上传。新电脑：安装 WorkBuddy，装同一云盘并登录，从云盘把目录同步到本地，如有自定义路径再重建软链接。

优点是以后再也不用手动搬；缺点是云盘有隐私顾虑——建议对 memory/ 目录单独加密后再同步。

## 方案二（进阶）：Git 仓库管理
适合有版本管理习惯的开发者：把 ~/.workbuddy/ 作为 Git 仓库托管到 GitHub/Gitea，利用版本历史做配置回滚。旧电脑 git init、git add、git remote add、git push；新电脑 clone 仓库到 $HOME/.workbuddy，如有 plugins 依赖再 git submodule update --init --recursive。

进阶玩法：用 .gitignore 排除 plugins/cache 等临时文件，只同步源码不同步构建产物；用 Git LFS 管理大型 theme.json 和二进制插件；用分支管理不同工作环境。优点是版本可追溯、支持团队共享、可离线；缺点是需要 Git 基础。

## 方案三（兜底）：U 盘直接拷贝
适合纯小白、临时换电脑、不想折腾云盘或 Git 的情况：把整个 .workbuddy 目录拷到 U 盘，新电脑上再拷回来。最笨，但最稳。

## 搬完怎么确认
三种方案没有最好，只有最适合。搬完之后逐项核对：身份文件在不在、Skill 能不能调用、MCP 连接器通不通、记忆文件有没有内容。这 14 项齐了，新电脑上的 WorkBuddy 才是「你的」那个 WorkBuddy，而不是一个失忆的新同事。
