# WorkBuddy 家庭免费云崩溃：0x8007045D 报错的完整排查
一台吃灰的 Ubuntu 笔记本、一块外接 SSD、加一个 Tailscale 组网，就是一个零成本的私有远程云盘。前面已经写过怎么把外接的 120G 共享云盘和 1T 固态挂上去，这次的问题出在「把旧笔记本变成远程云盘」之后：云盘一周没登录，就不见了。

尝试把内容复制到远程共享盘，直接失败。这个报错是「0x8007045D：I/O 设备错误」，通常是底层写入失败，不是权限问题。最大嫌疑是 USB 外接 SSD 掉盘、接触不良，或者 NTFS 在 Linux 下偶发不稳定。

满心欢喜往里拷文件，结果 Windows 冷冷甩给你一句这个错误。这篇记录的是踩坑、排查到解决的全过程，希望能帮你少走弯路。

## 一、我的「云盘」是怎么搭起来的
家里有台装了 Ubuntu的老笔记本，当服务器用。手头有块闲置的SSD，我想把它变成一个可以随时远程访问的网盘：

**服务器：**Ubuntu 笔记本（机械硬盘装系统 + USB 外接 SSD 当存储）；客户端：两台 Windows 工作本；组网：Tailscale，两台机器都装好、互联。

方案是在 Ubuntu 上用 Samba（SMB）共享 SSD，Windows 直接映射成 Z：盘。搭完之后，在 Windows 文件管理器里访问 \\100.x.x.x\ssd，输入账号密码，Z：盘就出来了，看着跟本地磁盘没两样。前期一切顺利。

## 二、故障来了：拷文件就报错
过几天，往Z：盘里复制一批资料，进度条刚动就弹出错误：试几次都一样。文件写不进去，云盘成了摆设。

## 三、排查：从「盘还在不在」开始
这种底层I/O错误，十有八九不是权限问题，而是存储链路断了。我按顺序查了三处。

先看盘还在不在、挂上没。这里就发现了一个关键矛盾。

lsblk 告诉我，SSD 现在叫 /dev/sdd1；但 df 里挂载源还写着 /dev/sdc1。也就是说，盘掉线重连后设备名从 sdc 变成了 sdd，而系统里旧的挂载记录没清掉。

接着看内核日志，里面反复出现读写失败。这行直接确认了判断：系统还在往那个已经不存在的 /dev/sdc1 上做读写，自然全是 I/O 错误。

为什么设备名会变？因为这块 SSD 是 USB 外接的（RTL9210B 桥接芯片的硬盘盒）。USB 接口一旦接触不良、供电不稳或触发省电休眠，盘就会短暂掉线，重连时 Linux 重新分配设备名。旧的挂载点就变成了一个「幽灵挂载」——路径还在，底下没设备了。

## 四、解决：清掉幽灵，重新挂载
既然找到了病根，处理就清晰了，一共三步。

第一步，强制卸掉陈旧的挂载。这里用的是「延迟卸载」——就算有程序占着，也先把挂载点摘下来，等占用释放后再真正断开。

第二步，按 UUID 重新挂载。fstab 里我配的就是按 UUID 挂载，它会自动定位到当前真实的 /dev/sdd1；也可以直接手动挂，更直观。

看到 OK，回到 Windows 再试复制——通了。Z：盘又能正常读写。

**一个小提醒：**Windows 正在访问 Z：盘时，在 Ubuntu 上 umount 会报 target is busy。记得先关掉 Z：盘的所有窗口，必要时 sudo systemctl stop smbd 再卸。

## 五、为什么会掉盘？怎么防？
修好了不等于根治。USB 外接盘当服务器存储，最大的软肋就是连接稳定性。

软件层面最容易踩的坑是 USB 自动省电——系统为了省电把 USB 口休眠了，盘就掉了。一条 udev 规则就能关掉。

硬件上换更强的连接，优先级是：换一根靠谱的短线 → 插主板原生 USB 3.0 口（别用扩展坞或前置面板）→ 换硬盘盒。如果还是频繁掉盘，最彻底的方案是把 SSD 装进笔记本内置 SATA 口，直接走机身总线，比 USB 稳得多。

## 六、两个容易误会的小细节
共享盘上出现 System Volume Information 文件夹，是 Windows 访问 NTFS 时自动生成的系统隐藏文件夹，不是病毒也不是坏道。平时在 Windows 里是隐藏的，走 Samba 才露出来，不用管它。

fstab 里用 UUID= 偶发报错：我发现 mount -a 有时会把 UUID=xxx 原样丢给 ntfs-3g，报「Failed to access volume 'UUID=…'」。改成显式设备路径更稳。

## 七、写在最后
这次故障从「报错」到「定位」其实只花了三步：lsblk 看设备名、dmesg 看内核日志、umount -l 清幽灵挂载。问题的核心从来不是 Samba 配置，而是底层存储链路断了。

给同样想用旧设备折腾私有云盘的朋友一个忠告：可以用 USB 外接盘，但别把它当生产存储。想长期稳定，要么换内置 SATA，要么至少把连接做扎实。
