# 把活交给WorkBuddy，把安全交给我们
处理财务报表、分析运营数据、整理会议纪要……这些原本需要几个小时甚至一两天的工作，现在WorkBuddy几分钟就能搞定。

随着越来越多的人开始把工作交给WorkBuddy，大家也许会好奇，WorkBuddy的安全机制是什么样的。

WorkBuddy携手腾讯安全，从系统架构安全、运行时安全、数据安全、身份认证与凭证安全等维度，为WorkBuddy构建了一套严谨、可验证的安全能力体系。一起来看看，这套体系是如何工作的。

系统架构如何保障全链路安全。

WorkBuddy支持多种权限模式，并配有安全中心，支持按需配置黑白名单。同时内置安全沙箱，提供安全运行环境，并在操作系统层面识别操作意图，拦截高危操作。

Agent 运行时的安全风险要如何避免。

攻击者通过精心构造的提示词，可能一步步诱导Agent进行违规操作。WorkBuddy围绕这一风险构建了“入口拦、运行检、兜底断”三道关卡：入口层通过输入清理和命令阻止列表拦截高风险操作；运行层通过上下文感知分析、隔离窗口和命令注入检测持续扫描异常指令，敏感操作需用户明确授权；兜底层以熔断机制提供最终安全屏障，层层防护，降低提示词注入攻击的风险。

当用户安装第三方Skill时，WorkBuddy会在安装前自动进行安全扫描，检测潜在的恶意脚本和风险行为，通过安全检测的Skill才能被启用。

WorkBuddy还引入了隔离沙箱，通过三个维度设了限制，Agent被诱导执行危险操作时，沙箱能有效降低风险扩散的可能：文件系统隔离，限定写入指定目录，防止越界修改；网络隔离，阻止非必要的网络请求；命令隔离，危险命令需确认或阻止。

与模型的对话数据会不会泄露。

这是用户最关心的问题。WorkBuddy在存储、传输、使用环节均有管控，确保数据流转可追溯、权限可控制。

存储环节，基于场景提供灵活的存储策略；传输环节，采用全链路 TLS 加密；使用环节，遵循最小权限原则，进一步提升数据安全性。同时，提供文件删除保护功能：包含批量文件删除确认，删除文件进入回收站，防止用户数据被AI误删丢失。

如何确保身份认证与凭证安全。

WorkBuddy接入腾讯统一身份OneID，在企业应用场景中，支持SSO 单点登录与多认证源对接，一次认证通行全套件；敏感操作自动触发二次认证；基于角色权限模型实现最小权限控制，离职即刻回收权限。

此外， OneID也即将接入个人场景，基于「一人一 OneID」统一账号体系，打通腾讯系 C 端应用身份，一次登录多端免登，应用间协作天然互通；账号与授权集中管控，统一风控合规。

API 密钥与令牌通过操作系统原生密钥链加密存储，运行时按需调取、用后即销。总之，WorkBuddy的安全底层逻辑是：帮你干活，但不把安全交出去。
