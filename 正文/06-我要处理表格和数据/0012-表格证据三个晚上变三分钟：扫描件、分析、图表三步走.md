# 表格证据三个晚上变三分钟：扫描件、分析、图表三步走
## 对方当庭甩出一叠手机拍的银行流水
办过一个民间借贷案子，对方搞证据突袭，当庭甩出一堆银行流水——不是扫描件，是让我当场用手机拍。

手机拍出来的表格是什么质量，做过的人都知道：歪斜、反光、模糊、字体变形。别说 OCR 了，人眼都费劲。

当时我花了整整三个晚上，用办公软件把那叠照片转成表格。那种「图配列」的复杂表格，转完之后格式错乱得一塌糊涂——单元格合并失效、行列错位、数字跑到不该在的地方。

然后还得在错乱的表里，用最原始的筛选功能，一条一条找关联方之间的交易。三个晚上，才拿到想要的那几条证据。

表格类证据，是大多数律师不擅长的证据类型。刑事案件、婚家案件、公司法律师，诉讼或非诉，都要处理这类材料，而多数文科出身的律师在这件事上有两个短板：不具备数据分析能力，也不愿意花几天学数据透视表。

## 现在这条路走通了：三个晚上变三分钟
AI Agent 能力起来之后，这件事的门槛被拆掉了。整个流程不需要你会公式、不需要写代码、不需要懂数据透视表——你只需要会说话。

核心工具是 WorkBuddy 里的 MinerU 文档提取 Skill，这是很多人反复推荐的一个必装技能。

**流程分三步：**把图片或扫描件变成干净的 Excel、用自然语言做数据分析、一键生成图表。三步都在同一个对话框里完成。

**先说清一件事：**三步的顺序不能颠倒。数据不干净，后面两步全是垃圾进垃圾出。

## 第一步：把扫描件变成干净的 Excel，这是最关键的一步
**操作比想象中简单：**把扫描件或照片直接上传到对话框，告诉 WorkBuddy「把这份表格转成 Excel」。

**实际跑起来是这样的：**上传一份 77MB 的银行流水 PDF，输入「调用 miner u skill 把附件转为 excel」，它会回一句「MinerU extract 模式提取中，预计需要几分钟」，两分钟后给出结果。

结果不是一句「已完成」，而是一组结构化信息：交易笔数 2,425 笔、日期范围 2021-05-21 到 2024-10-17、收入合计、支出合计、净额。生成两个工作表：流水明细和汇总统计，颜色区分收支，隔行底色便于阅读。

**后台实际发生的事是：**MinerU 先对图片做 OCR，转成 Markdown 格式的结构化文本，再从 Markdown 转成 Excel。中间这步 Markdown 是必要的——它充当「标准化中间层」，把各种乱七八糟的扫描质量统一成一套规则，再输出 Excel。

知道这个链路有实际用处：中间产物出问题，你能判断是识别错了还是转换错了。

## 但有一个重要提醒：OCR 会出错，必须人工核实
MinerU 的准确率大概在 90% 到 95% 之间。对照片类表格——尤其光线不好、角度倾斜、字迹模糊的情况——错误率会更高。

所以拿到 Excel 之后，一定要做人工核实。关键金额、日期、当事人名称，逐项核对，不能偷懒。

这一步不能省，尤其在证据场景。一个识别错的小数点，在庭上可能就是致命的。

把这条当成流程的一部分，而不是可选项：OCR 出表、人工核对金额和日期、确认无误再进入分析。

## 第二步：用自然语言做数据分析，不用公式不用代码
有了干净的 Excel，在同一个对话框里继续说人话就行。

**比如这几句：**帮我找出与某个人之间的所有交易记录；按金额从大到小排列，取前三位；筛选出某年某月到某月之间，金额超过某数的转账。

WorkBuddy 会在后台用 Python 完成这些分析，把结果直接展示给你。你看不到代码，不需要懂代码，拿到的是结果。

对文科出身的律师来说，这是真正的变化。过去想做这种分析，要么求人——找懂 Excel 的同事或者花钱；要么硬啃——花几天学数据透视表，做完就忘。现在只需要把问题用自然语言说出来。

**这里有个隐性收益：**你提的问题会越来越像法律问题，而不是操作问题。以前你被工具限制着问「怎么筛」，现在可以直接问「哪些交易构成异常」。

## 第三步：一键生成图表，法庭上一张图胜过十页文字
**分析完继续说需求就行：**把各关联方的交易金额画成柱状图；按月份统计交易笔数画成折线图；各类交易金额占比画成饼图。

它会用图表库直接生成可视化结果，柱状、饼状、折线、散点都行。

这一步在法庭上的价值被低估了。一张清晰的图表胜过十页文字说明——法官看柱状图，一秒就能看懂资金流向；看饼图，一眼就能判断交易结构。

这种能力过去是少数有数据分析背景的律师的专利，现在基本没有门槛了。

## 四条经验，都是踩过才知道的
第一，优先要原件。对方给的是 PDF 或扫描件，尽量争取原件或高清扫描件。照片是最差的输入，OCR 准确率会断崖式下降，后续核实的工作量急剧上升。

第二，分步确认，不要一步到位。先转 Excel 核实准确性，再做分析确认结果合理，最后出图表。不要在数据还没核实的时候直接要求「生成一份完整分析报告」——垃圾进、垃圾出。

第三，善用对话历史。同一份 Excel，可以在同一个对话框里不断追加分析需求，它会记住上下文，你不用每次重新上传、重新描述。这是它比传统工具强的地方：分析是一段持续的对话，不是一次性的操作。

第四，图表要说清用途。不要只说「要饼图」，要说想表达什么，比如「画一张饼图展示各关联方交易金额占比，标注百分比」。指令越具体，结果越能用。

## 这套流程能搬到哪里
不要把这篇当成「律师专用」。这套三步流程的本质是：把非结构化的图片表格变成结构化数据、用自然语言查询、输出可视化结论。

做财务对账的人可以用它处理供应商发来的照片对账单；做采购的可以用它整理报价单照片；做审计的可以用它处理扫描凭证。凡是「对方只肯给照片版表格」的场景，都用得上。

**唯一的纪律还是那条：**OCR 不是 100%，关键数字必须人工核对。这不是对工具的不信任，这是专业流程该有的样子。

你不再是在学一个新工具，你是在对一个懂技术的同事说话。把最难的识别、结构化、分析、可视化一条龙交出去，自己专注在判断和策略上——这才是这件事真正的价值。
