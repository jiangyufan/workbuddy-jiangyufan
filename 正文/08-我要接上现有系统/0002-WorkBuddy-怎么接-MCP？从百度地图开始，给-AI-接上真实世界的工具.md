# WorkBuddy 怎么接 MCP？从百度地图开始，给 AI 接上真实世界的工具
面向刚开始接触 AI Agent 的普通用户，本文不讲协议源码，只讲 MCP 是什么、能做什么，以及如何在 WorkBuddy 里接入第一个 MCP。

很多人第一次使用 AI，最先体验的是写文章、改文案、总结文件、解释代码。这些任务有一个共同点：材料已经在对话框里，AI 只要理解和生成就可以了。

但下面这些问题就不一样了：帮我找学校附近适合自习的咖啡馆，再规划步行路线。看看我今天有没有需要马上回复的邮件。统计项目数据库里本月新增的用户，并按来源分类。找出 GitHub 仓库里还没有处理的 Bug。整理过去三个月的周报，告诉我哪些问题一直没有解决。

这些信息分别在地图、邮箱、数据库、代码仓库和文件系统里。AI 本身并不能凭空进入这些地方，它需要一个连接外部工具的办法。这就是 MCP 要解决的问题。

本文先从 WorkBuddy 里的“连接器”讲起，解释 MCP 和普通聊天有什么不同。然后我们用百度地图 MCP 做一次入门配置。

## 一、先理解 WorkBuddy 里的“连接器”。
可以把 AI 想成一个很聪明的助理。

它能帮你写总结、做分析，也能按照你的要求整理文件。但如果它没有邮箱、网盘、地图或项目系统的访问权限，它就只能等你把内容复制过来。

你把一份会议通知粘贴给它，它可以帮你提炼时间和地点；但如果你只说“帮我看看今天有没有重要邮件”，它就需要先进入邮箱，才能真正开始工作。

WorkBuddy 里的连接器，作用就是让 AI 接触到原本不在对话框里的数据和工具。接入以后，你可以继续用自然语言提需求，WorkBuddy 再根据任务去调用对应的服务。

例如：接上地图服务后，可以查地点、找附近的店、规划路线。接上邮箱或日历后，可以查邮件、找会议、整理待办。接上文件或知识库后，可以在资料库里检索内容，再生成总结。接上 GitHub 后，可以查看仓库、Issue 和代码变更。接上数据库后，可以读取业务数据，做统计和简单分析。

接上企业系统后，可以查询客户、订单、工单或库存信息。

这里要注意，连接器不是“让 AI 变得更聪明”的按钮。它更像是一条通道，让 AI 在完成任务时可以访问新的数据源和工具。

## 二、MCP 到底是什么。
MCP 的全称是 Model Context Protocol，中文一般译作“模型上下文协议”。对普通用户来说，不需要一开始就理解协议中的每个字段。先把它理解成下面这句话就够了：MCP 是一套让 AI 应用连接外部数据、工具和服务的通用方式。

以前，一个 AI 应用想接地图，需要单独开发地图接口；想接邮箱，又要开发一套邮箱接口；想接数据库，还要重新处理数据库的连接和返回结果。不同工具之间的接法各不相同，开发和维护都比较麻烦。

MCP 试图把这部分连接方式做得更统一。提供工具的一方可以提供 MCP Server，WorkBuddy 这类 AI 应用作为客户端去连接它。这样，地图、知识库、GitHub 或企业系统都可以用类似的方式接入。

关系可以简单画成这样：

你提出任务 ↓ WorkBuddy 理解任务 ↓ 通过 MCP 选择并调用工具 ↓ 地图、邮箱、数据库、GitHub、知识库等外部服务 ↓ WorkBuddy 整理结果并回复你。

如果把连接器比作一把钥匙，MCP 更像是约定钥匙和锁的接口。不同服务可以制作自己的“钥匙”，AI 应用按照约定的方式使用它们。

所以，MCP 不是某一个具体软件，也不是只有程序员才能使用的技术。对普通用户来说，MCP 的价值在于：你配置一次，之后可以通过对话调用外部工具。

## 三、MCP 能做什么。地图只是其中一个例子。
理解 MCP，最好的办法不是继续背定义，而是看它能解决哪些实际问题。

1. 地图和出行

接入地图 MCP 后，你可以这样提问：帮我找学校附近 2 公里内适合学习的咖啡馆，列出地址、距离和营业时间。我明天从虹桥站去会议地点，比较驾车、公交和步行方案。帮我规划一条周末骑行路线，中途安排两个可以休息的地方。

这类任务需要地点检索、坐标转换、路线规划或天气信息。AI 负责理解你的要求，地图 MCP 负责提供相应的地图服务。

1. 文件和知识库

如果 AI 能访问你的项目文件或知识库，它就不必每次都等你复制资料。读一下这个项目过去三个月的周报，整理出反复出现但还没有解决的问题。在课程资料里找到所有讲到 Transformer 的内容，按章节汇总。根据知识库里的报销制度，告诉我这次出差需要准备哪些材料。

这里的重点不是让 AI 记住所有资料，而是让它在需要时可以检索相关内容。资料更新后，检索到的结果也可以随之变化。

1. 邮箱、日历和待办

对于学生和上班族，这类连接器很容易用上：找出今天收到的、需要我回复的邮件，按紧急程度排序。查看下周一到周三的日历，找一个和同学都空闲的两个小时。把邮件里的会议时间整理成待办事项。

如果连接器支持写入操作，AI 还可能帮你创建日历事件、草拟回复或更新待办。不过涉及发送邮件、修改日历、删除数据等操作时，建议先让 AI 生成方案，再由你确认后执行。

1. GitHub 和开发工具

MCP 也可以连接代码仓库和开发工具。例如：看看这个仓库最近有哪些未处理的 Bug，按影响范围分组。总结最近一周合并的 Pull Request，并指出可能需要补测试的地方。找出和登录失败有关的 Issue，看看有没有重复问题。

这对正在做课程项目、毕业设计或日常开发的人很有帮助。AI 不只是在对话框里解释代码，还可以读取项目中的实际信息。

1. 数据库和业务系统

接上数据库或业务系统后，AI 可以参与一些查询和分析工作：统计本月新增用户，按渠道分组，并和上个月比较。查一下这个客户最近半年的订单和未关闭工单，整理成一页摘要。找出库存低于安全线的商品，生成补货清单。

这类场景要特别注意权限和隐私。给 AI 的数据库账号应该只开放完成任务所需的权限，敏感数据也不应该随意接入个人环境。

1. 多个工具一起完成一个任务

MCP 更有意思的地方，在于一个任务可能需要多个工具配合。比如你说：我下周去杭州开会，帮我查会议地点附近的酒店，比较从高铁站到酒店的路线，再看看当天是否需要带伞。

这句话背后可能包含几个动作：先确定会议地点，搜索附近酒店，再规划路线，最后查询天气。对你来说是一句话，对 AI 来说是一组需要分步执行的任务。

如果相关服务都已经接入，WorkBuddy 可以根据任务判断什么时候调用哪个工具，再把结果整理成一份可读的方案。

这也是 MCP 和普通问答的区别之一。普通问答主要依赖模型已有的知识和你提供的内容；接入 MCP 后，AI 可以在任务过程中访问外部服务。

当然，能不能自动完成多步任务，还取决于 WorkBuddy 当前版本、模型能力、MCP 服务本身以及账号权限。第一次使用时，建议先从一个简单任务开始，不要一上来就要求它同时操作多个系统。

## 四、快速入门：在 WorkBuddy 里接入百度地图 MCP。
WorkBuddy 自带了很多连接器，大多数情况下直接搜索名称、点击添加即可完成配置，操作比较简单。本文不展开介绍这部分内容，下面重点讲一个需要手动配置的例子：百度地图 MCP。

百度地图适合做第一个 MCP，原因很简单：结果容易验证。你搜一个地点、规划一条路线，马上就能判断工具有没有正常工作。

百度地图 MCP Server 提供的能力包括地理编码、逆地理编码、地点检索、地点详情、路线规划、批量算路等。官方文档还列出了天气、行政区划、多维检索和地图调起等能力，具体可用工具会随服务版本和权限变化。
