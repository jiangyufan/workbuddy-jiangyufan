# WorkBuddy这5个文件没配置难怪不好用！
WorkBuddy · 深度配置指南。WorkBuddy。这5个文件不配置。难怪用起来「不够懂你」。别的AI没有的能力，90%的用户都浪费了。你花了很多时间用 WorkBuddy，但它好像还是不够懂你。

你说"写一篇公众号"，它给的风格每次都不一样。你说"用我的配色"，它一脸茫然。你让它"记住这个偏好"，下一次它又忘了。

问题不出在 WorkBuddy 本身——作为一款 AI 助手产品，它的底层能力足够强。但它出厂时不认识你。

市面上大多数 AI 助手是「一次性对话」——每次打开都是新的开始。但 WorkBuddy 不一样：它设计了一套独一无二的「文件驱动记忆系统」——5个配置文件，让你把 AI 从「通用」调教成「专属于你的工作搭档」。关键是，90%的 WorkBuddy 用户从没碰过它们。

SOUL.md 是 WorkBuddy 的「人格配置文件」。它决定了 AI 用什么语气跟你说话、遇到事情怎么判断、什么是它该做和不该做的。你可以把它理解为——「给AI写一份岗位说明书」。

为什么它最重要。

没有 SOUL.md，WorkBuddy 就是一个「通用的、没有个性的 AI 助手」——说话风格随机、做事方式机械、遇到边界情况全靠模型自己猜。

有了 SOUL.md，你可以告诉它：▸你希望它怎么说话——干练直率还是温柔耐心。▸你希望它怎么做事——先问再干，还是直接上手。▸你希望它守什么底线——隐私原则、外部操作边界。⚙️ 怎么配置。在项目根目录或 ~/.workbuddy/ 目录下创建 SOUL.md，核心包含三部分：

# SOUL.md - 你是谁## 核心真理- 帮人解决问题，不废话。行动比语言更有说服力。- 有主见。可以不同意用户，可以有自己的偏好。- 先自己想办法，实在不行再问用户。## 边界- 私事不外传。不确定的事，先问再动。- 不在群聊里替用户说话。## 氛围- 该简洁时一句到位，该详细时掰开揉碎。- 不做机器人，做有温度的搭档。

配置前后对比。场景。❌ 未配置 SOUL.md。✅ 配置后。你让它写方案。给一个泛泛的模板，需要反复追问。直接按你的风格出稿，结构符合公司习惯。你问它"这样做行不行"。当然可以，没问题"——永远说好。我倾向方案B，因为A有个隐患……"——有主见。

你要它操作外部文件。直接动手，可能踩坑。先确认再执行，守好边界。 文件二：IDENTITY.md — AI的身份。IDENTITY.md — 定义AI"是谁"。路径：~/.workbuddy/IDENTITY.md 或 项目根目录/IDENTITY.md。

如果说 SOUL.md 定义的是「性格」，那 IDENTITY.md 定义的就是「身份标签」——它叫什么名字、扮演什么角色、跟你是什么关系。这些信息会直接影响 AI 在对话中的自我认知和行为表现。

为什么不能跳过。

没有 IDENTITY.md，WorkBuddy 就不知道自己该叫什么、该以什么身份跟你协作。它可能一会自称"AI助手"，一会又是"智能体"，缺乏一致性。更重要的是——角色定位决定了它对待你任务的态度。

⚙️ 配置示例。

# IDENTITY.md - 我是谁。Name:阿福Creature:AI 助手 — 取"福星高照"之意Vibe:专业严谨、有温度、不废话Emoji:我是产品经理小明的AI助手，帮他做竞品调研、用户分析。

❌ 未配置。对话中的自称。随机切换，缺乏人格感。统一自称，人格一致，像真正的搭档。对你的称呼。用户" "你" 生硬切换。固定称呼，关系感拉满，更像协作而非操作工具。任务主动性。等指令，被动执行。知道自己的角色定位，主动多想一步。 文件三：USER.md — 用户画像。

USER.md — 告诉AI"你是什么样的人"。路径：~/.workbuddy/USER.md 或 项目根目录/USER.md。

USER.md 是 AI 了解你的「用户画像卡」——你是谁、做什么工作、有什么偏好、用什么工具、喜欢什么风格。WorkBuddy 会基于这些信息来调整自己的输出，让它更「像为你定制的」。

为什么这是最被低估的一个。

大多数人以为"用多了AI自然会懂我"，但实际上，AI 的上下文窗口有限，不可能从零散的对话中拼凑出完整的用户画像。USER.md 是一次性把关键信息喂给它，让它从一开始就懂你。

# USER.md - 关于我的主人Name:小明Role:互联网产品经理City:上海## 工作内容- 产品规划：负责公司SaaS产品的路线图- 竞品调研：定期输出行业分析报告- 团队沟通：对接开发、设计、运营## 内容偏好- 报告用PPT格式，结构清晰，图表丰富- 方案文档用Markdown，便于版本管理- 数据分析默认输出折线图+表格对比- 沟通风格：直接给结论，不必铺垫。

写竞品报告。不知道你要什么格式、什么深度，每次都重新解释。默认出 PPT 格式，图表丰富，结构清晰。分析产品数据。给一串原始数字，不直观。自动输出折线图 + 对比表格 + 一句话结论。方案文档。可能给 Word 格式，不好维护。知道你要 Markdown，便于版本管理和协作。

USER.md 是 ROI 最高的一个文件。你只要花10分钟写一次，之后每一次对话，WorkBuddy 都会自动带上这些偏好。再也不用重复说"帮我写一个竞品分析报告，要PPT格式、图表丰富……"了。

文件四：用户级 MEMORY.md — 跨项目记忆。用户级 MEMORY.md — 所有项目通用的长期记忆。路径：~/.workbuddy/MEMORY.md。

这是 WorkBuddy 三层记忆体系中的第二层——它存储的是「跨项目通用的信息」：你的长期偏好、通用工作习惯、以及那些「不管在哪个项目里都应该记住」的事情。

它和 SOUL/USER 有什么区别。

简单说：SOUL.md + IDENTITY.md + USER.md 是静态身份档案（你手动写的），而用户级 MEMORY.md 是动态积累记忆（AI 在长期对话中持续更新写入的）。前者是「简历」，后者是「工作总结」。

⚙️ 哪些内容适合写在这里。▸竞品报告统一输出 PPT 格式，不输出 Word。▸数据可视化固定用折线图+表格，不做纯文字。▸方案文档必须 Markdown 格式，便于 Git 版本管理。▸涉及多个产品线时，注意区分品牌调性。 有 vs 没有的对比。

❌ 无 MEMORY.md。✅ 有 MEMORY.md。换了一个新项目。AI 忘掉你之前所有的偏好，从头开始。自动带上通用偏好，无缝衔接。涉及不同产品线。混淆不同品牌风格，输出内容串味。精确区分每个产品的定位和风格。重复性规范。每次都要重新说明"不要 Word 要 Markdown"。

一次写入，永久生效。 文件五：项目级 MEMORY.md — 当前项目记忆。项目级 MEMORY.md + 每日日志 — 本项目的专属记忆。

这组文件是干什么的。WorkBuddy 为每个项目维护一套独立的记忆系统，包含两个文件：▸项目 MEMORY.md：记录项目级的长期约定——技术选型、架构决策、命名规范、配色方案等。▸每日日志 (YYYY-MM-DD.md)：自动记录每天在这个项目里做了什么，形成工作台账。

为什么项目级别的记忆至关重要。

想象一下：你上周跟 WorkBuddy 在这个项目里敲定了配色方案、选好了技术栈、还定了几条排版规则。这周打开一个新会话——如果没有项目级记忆，这些全白费了。AI 只能从零开始。

有了项目级记忆，AI 每次打开项目都会自动加载这些约定。实现真正的「项目连续性」。⚙️ 实际效果示例。以竞品分析项目为例，MEMORY.md 里可能存着：

# 项目约定 - SaaS产品竞品分析报告格式PPT，每页一个核心观点，图表占比 > 40%数据来源优先使用公司数据平台，其次公开财报交付标准PPT报告 + 数据源Excel + 关键发现摘要命名规范报告文件名：日期_产品名_竞品分析_v版本号。

对比。❌ 无项目记忆。✅ 有项目记忆。新会话写文章。不知道用哪个配色、什么排版规范。自动延续上次确定的配色和规范。一周后回来。全忘记上周做了什么调整。每日日志回溯，一秒定位。多人协作。每个人各写一套风格，混乱。统一规范，团队输出一致。
